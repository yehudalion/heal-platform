## חלק א' — מה נבנה (בשפה פשוטה)

### 1. שלושת המסכים של הפינה — עכשיו קיימים באמת

עד היום היה רק מסך תרגול (שידע להציג רק השלמות), ודשבורד שנשען על טבלה
שלא קיימת ולכן לא באמת עבד. עכשיו:

- **למידה** (`/listening/learn`) — מסך חדש עם השיעור האחד של הפינה: "לאן
  הקטע הולך ומתי הוא משנה כיוון", כולל דוגמה באנגלית שבה **מילת הקישור
  מודגשת בצהוב** — בדיוק הרעיון שביקשת ("שיהיה מודגש בו מילת הקישור").
- **תרגול** (`/listening/session`) — שודרג: יודע עכשיו להציג גם קטעי
  lecture_qa עם שתי שאלות (הקטע מושמע פעם אחת, השאלות באות בזו אחר זו,
  בלי השמעה חוזרת — כמו במבחן). כל פגישה: חימום + 2 השלמות + קטע אחד.
- **ניתוח** — שניים: סיכום רך בסוף כל פגישה ("בסשן הזה X מתוך Y הטעויות
  היו סביב שינוי כיוון"), ומסך מצטבר חדש (`/listening/analyze`) שמראה את
  הפגישות האחרונות ועל מה היו הטעויות. הניסוח תמיד על *הסשן*, אף פעם לא
  על התלמיד — לפי כלל הרווחה.
- **הדשבורד** נכתב מחדש: שלושה כפתורים (למידה/תרגול/ניתוח) + נתוני אמת
  (כמה שאלות נענו, אחוז דיוק, ימים לבחינה). הוסרו: "ימים ברצף" 🔥 (מנוגד
  לכלל הרווחה), ציון מוכנות מומצא, ובורר "4 מיומנויות" שלא מוגדרות בשום
  מסמך.

בדקתי שהאפליקציה **נבנית בהצלחה** (vite build עובר). כדי *לראות* תוכן
במסכים צריך לפרסם קטעים — זה נשאר בידיים שלך (חלק ב', צעד 4).

### 2. מנת ייצור א' — 6 קטעים חדשים במאגר

לפי ה-roadmap, מנה א' = 6 קטעים שסוגרים את סוג השאלה שחסר בכיול
(vocab_in_context). נבנתה, עברה את כל השערים, ונכתבה ל-DB — **לא מפורסמת,
מחכה לביקורת שלך**. פירוט מלא + התמלילים: `docs/lecture_qa_production_batchA_2026-08-14.md`.

בקצרה: 2 קצרים, 2 בינוניים, 2 ארוכים; 3 הרצאות + 3 דיאלוגים (כולל דיאלוג
מדריך+מבקר בטחנת רוח); 10 שאלות מכל הסוגים כולל negative, opinion
ו-vocab_in_context; 40 הסברים בעברית עם ציטוטים מדויקים. שני בודקים
עיוורים נפרדים: פתירות 10/10; דליפה — אותה תבנית מוכרת מהכיול, כולל תיקון
אחד אמיתי שהבודק תפס (תשובת ה-NOT הייתה מנומקת-מדי-בקלות).

### 3. ההפסקות (SSML) — נבדק, נמדד, חובר

שאלת אותי אם זה קריטי ואם אני יכול לבדוק לבד. **בדקתי לבד** — עם שני
הקבצים שהניסוי שלך יצר (`_ssml_test_plain/paused.mp3`) ומדידת שקט ממוחשבת:

- בהקלטות האמיתיות ~23%–38% מהקליפ הוא שקט (הפסקות).
- הרינדורים שלנו בלי הפסקות: 18%–23% — **מתחת לטווח האמיתי**. זה מדיד בכל
  6 הקטעים החדשים.
- אותו קטע עם הפסקות: 32% — **בתוך הטווח האמיתי**.

מסקנה: כן, זה פער אמיתי ומדיד (גם אם זה לא מה שהתכוונת ב"תמיד אותו צליל").
חיברתי את ההפסקות לשני סקריפטי הרינדור — מעכשיו כל רינדור כולל אותן
אוטומטית (אפשר לכבות עם `--no-ssml`).

**ומה שכן התכוונת** — אשמח שתגיד לי במילים שלך מה בכל זאת מפריע בצליל,
אחרי שתשמע את הרינדור הבא (שיהיה גם עם 7 קולות שונים וגם עם הפסקות).

### 4. תיקונים קטנים

- `qa_listening_audio.py` — השגיאה שקיבלת (`--type is required`) הייתה
  באשמתי (הוראה חסרה במדריך). עכשיו יש מצב חדש `--type lecture_qa` שמתאים
  לתיקייה המעורבת, ומדלג אוטומטית על קבצי העבודה הזמניים.
- הרצתי אותו בעצמי על 6 הקטעים שרינדרת: **5/6 עברו**. אחד נכשל —
  קטע בתי הקפה (s60) יצא 70 שניות דיבור במקום 56–62. זה עניין של קצב
  ההקראה, מפורט בחלק ג'.
- שני מסכי הבדיקה הישנים (test-page, item-test-page) נותקו מהאפליקציה
  כפי שכבר אושר ב-SITEMAP. את הקבצים עצמם אי אפשר למחוק בלעדיך (חלק ב').
- SITEMAP.md עודכן לשקף את כל המצב החדש, כולל ביטול החריג הבריטי באיות.

## חלק ב' — המדריך שלך, שלב אחרי שלב

**מה תצטרך:** מחשב עם התיקייה של הפרויקט, כ-20 דקות.

### צעד 1 — לרנדר מחדש את האודיו (עם הקולות החדשים + ההפסקות)

1. פתח טרמינל (התחל ← הקלד `cmd` ← Enter).
2. עבור לתיקיית הפרויקט:
   ```
   cd C:\Users\Myriam\heal
   ```
3. קודם ה-6 קטעים החדשים של מנה א' (רק להם אין עדיין אודיו):
   ```
   node scripts/generate-lecture-qa-audio.js --all
   ```
   **מה תראה אם הצליח:** שש שורות `✅` עם שמות קולות שונים.
   **אם יש שגיאה:** העתק לי את כל הפלט ואל תמשיך.
4. עכשיו רינדור מחדש של כל 106 הקבצים הקיימים (100 השלמות + 6 מהכיול),
   כדי שיקבלו גם קולות מגוונים וגם הפסקות. שים לב — זה דורס את הקבצים
   הקיימים ולוקח כ-15 דקות:
   ```
   node scripts/generate-listening-audio.js --all --force
   node scripts/generate-lecture-qa-audio.js --all --force
   ```

### צעד 2 — בדיקת איכות אוטומטית

5. שתי פקודות:
   ```
   python3 scripts/qa_listening_audio.py scripts/audio_output --type completion --strict
   python3 scripts/qa_listening_audio.py scripts/audio_output_lecture_qa --type lecture_qa --strict
   ```
   (אם `python3` לא מוכר אצלך, נסה `python` במקום.)
   **מה תראה:** טבלה עם שורה לכל קובץ ו-`ok` או `FAIL`.
   **צפוי מראש:** ייתכנו כשלונות אורך על קטעי s60/s90 — ראה חלק ג' סעיף 1.
   העתק לי את השורה התחתונה ("X/Y passed") ואת שורות ה-FAIL אם יש.

### צעד 3 — בדיקת האוזן (הכי חשוב)

6. פתח את `audio_ab_check.html` (לחיצה כפולה בתיקיית הפרויקט) והשווה שוב
   מול ההקלטות האמיתיות — הפעם עם הקולות המגוונים וההפסקות.
7. כתוב לי בשיחה: לכל זוג — "זהה / הבדל קל / שונה בבירור", ומה עדיין
   מפריע לך בצליל, במילים שלך.

### צעד 4 — לראות את הפינה החדשה בדפדפן

8. בטרמינל:
   ```
   cd C:\Users\Myriam\heal\artifacts\heal
   npx vite
   ```
   **מה תראה:** כתובת כמו `http://localhost:5173` — פתח אותה בדפדפן.
9. היכנס לחשבון ← פינת האזנה. תראה את הדשבורד החדש עם שלושת הכפתורים.
   מסך הלמידה עובד מיד. **התרגול יגיד "אין פריטים זמינים"** — כי שום קטע
   לא מפורסם. זה מכוון: פרסום הוא החלטה שלך בלבד.
10. כדי לפרסם לניסיון רק את מנת הכיול שכבר אישרת (6 קטעים) — הרץ ב-SQL
    Editor של Supabase:
    ```sql
    UPDATE listening_lectures SET is_published = true
    WHERE generation_batch = 'LQA-CAL2';
    ```
    ואז רענן את הדפדפן ונסה פגישת תרגול מלאה, כולל קטע עם שתי שאלות.
    (את מנת LQA-PROD-A פרסם רק אחרי שתקרא ותאשר אותה — צעד 5.)
